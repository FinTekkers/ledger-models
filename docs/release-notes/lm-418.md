# LM-418: "arm" renamed to "input type" in the ProductInput helpers

**Patch release.** No proto field, message, field number or enum value changes, so the wire format is the same. The old names keep working for this release as deprecated aliases. They will be removed in a later release.

## Why

Plan LM-376 called each field of the `ProductInput` oneof (`bond`, `tips`, `frn`, `mbs`, `equity`, `cash`) an "arm". In fixed income, ARM also means an adjustable-rate mortgage, a common MBS collateral type, so names like `armFor` would read ambiguously once MBS work starts. The term is now **input type**.

## Renamed names

Each old name only calls the new one.

| Language | Old (deprecated) | New | Marker |
| --- | --- | --- | --- |
| Java | `ProductInputs.armFor(SecurityProto)` | `ProductInputs.inputTypeFor(SecurityProto)` | `@Deprecated` |
| Java | `ProductInputs.measuresForArm(String)` | `ProductInputs.measuresForInputType(String)` | `@Deprecated` |
| Java | `MissingMarketDataError.getArm()` | `MissingMarketDataError.getInputType()` | `@Deprecated` |
| Python | `product_inputs.arm_for(security)` | `product_inputs.input_type_for(security)` | `DeprecationWarning` |
| Python | `product_inputs.measures_for_arm(arm)` | `product_inputs.measures_for_input_type(input_type)` | `DeprecationWarning` |
| Python | `MissingMarketDataError.arm` | `MissingMarketDataError.input_type` | `DeprecationWarning` |
| Python | `MissingMarketDataError(arm=...)` | `MissingMarketDataError(input_type=...)` | `DeprecationWarning` |
| JS/TS | `armFor`, `measuresForArm`, `measuresForArmIn` | `inputTypeFor`, `measuresForInputType`, `measuresForInputTypeIn` | `@deprecated` |
| JS/TS | `ValuationArms` (class and type), `parseValuationArms`, `shippedValuationArms` | `ValuationInputTypes`, `parseValuationInputTypes`, `shippedValuationInputTypes` | `@deprecated` |
| JS/TS | `MissingMarketDataError.arm`, and `.arm` on a resolved entry | `.inputType` | `@deprecated` |
| Rust | `arm_for`, `measures_for_arm` | `input_type_for`, `measures_for_input_type` | `#[deprecated]` |
| Rust | `Arm`, `ValuationArms` (type aliases) | `InputTypeEntry`, `ValuationInputTypes` | `#[deprecated]` |
| Rust | `parse_valuation_arms`, `shipped_valuation_arms` | `parse_valuation_input_types`, `shipped_valuation_input_types` | `#[deprecated]` |
| Rust | field `MissingMarketDataError.arm`, field `InputTypeEntry.arm` | method `input_type()` | `#[deprecated]` |

New, with no old counterpart: a loader that takes a whole `hierarchy.json` root — Java `ProductInputs.fromHierarchy` (package-private), Python `_ValuationInputTypes.from_hierarchy`, JS `valuationInputTypesFromHierarchy`, Rust `valuation_input_types_from_hierarchy`.

`requiredMarketData` / `required_market_data` keeps its name and signature; only its doc comment changes.

### Rust fields

Rust has no field aliases. Renaming a public field would break any code that reads `e.arm` or builds the struct with `arm:`, so both fields keep the name `arm` for this release, marked `#[deprecated]`. Read them through the new `input_type()` method. A struct literal with `arm:` still compiles, with a deprecation warning. The fields are renamed in the release that removes the aliases.

## `hierarchy.json`

`schema_version` is now `1.4`. The `valuation_arms` key is now `valuation_input_types`, and each entry's `arm` field is now `input_type`. Every entry, its `coupon_types`, its `requires` list and the `unpriced` list are unchanged.

For this release every loader still reads a file that uses the old key or the old entry field, and gives the same mapping. A file with both root keys, or an entry with both fields, is rejected as a broken registry. Code that reads the raw JSON key itself must move to the new names (see `ledger-models-protos/registry-versioning.md`).

## Error text

Messages now say "input type" where they said "arm":

- `missing market data CPI_U for arm tips` → `missing market data CPI_U for input type tips`
- `No valuation arm for product_type FX_SPOT, …` → `No valuation input type for product_type FX_SPOT, …`
- `no ProductInput arm is set` → `no ProductInput input type is set`, and the wrong-field message the same way.

Error types, `FieldViolationProto.field` paths (e.g. `tips.cpi`) and gRPC codes are unchanged. Services that compare message text must update it.

## Other notes

- JS `MissingMarketDataError.arm` is now a getter on the prototype, so `Object.keys(err)` no longer lists it.
- Renamed files: `docs/adr/valuation_input_types.md`, `docs/adr/product_input_engine_input_types.md`, `ledger-models-protos/fixtures/valuation_input_types_cases.json`, `test-fixtures/catalog/measures-for-input-type.json`.
- ledger-service, valuation-service and ui-service move to the new names in their own items.
