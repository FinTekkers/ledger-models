# LM-415: `PriceTypeProto` comments state the unit of `RATE` and `PERCENTAGE`

**Patch release.** Comment-only change. No enum value is added, renumbered, renamed, removed or deprecated, so the wire format is the same. Consumers have nothing to do.

## What changed

| Value | Comment now says |
| --- | --- |
| `PERCENTAGE = 2` | A price as a percentage of par, e.g. `99.75` = 99.75% of par. Never a rate; rates use `RATE`. |
| `RATE = 5` | A reference-rate fixing (SOFR, 13-week T-bill) in percent per annum as published, e.g. `4.32` = 4.32%. Same unit as `ReferenceRateFixingProto.rate`. |

`RATE` is **not** deprecated. A rate never shares a price type with a price, so a reader can tell a T-bill price (`98.94`, `PERCENTAGE`) from its rate (`4.215`, `RATE`) without the product type. The reasoning is in `docs/adr/frn_reference_rate_fixings.md`, amendment LM-415.

The regenerated Java and Rust bindings carry the new doc comments. Python and JS bindings are unchanged.
