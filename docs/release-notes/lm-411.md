# LM-411: `security_input` and `price_input` removed from `ValuationRequestProto`

**Breaking change** (owner-approved breaking 1.x release, filed by Plan LM-376).

## What changed

- `ValuationRequestProto.security_input` (field 20) and `ValuationRequestProto.price_input` (field 22) are removed.
- Field numbers **20** and **22** and the names `security_input` and `price_input` are `reserved`. They will never be reused.
- `position_input` (21), `asof_datetime` (23), `measures` (30) and `product_input` (70) are unchanged. `ValuationResponseProto` and the `RunValuation` RPC are unchanged.
- Rust: `Error::MissingSecurityInput` and `Error::MissingPriceInput` are deleted. Code that matches on them no longer compiles.

## What to use instead

Build `product_input` with the ledger-models builder, then the request with `ValuationRequests.typed`:

| Language | Builder |
| --- | --- |
| Java | `ProductInputs.forSecurity(security, price, marketData)`, then `ValuationRequests.typed(asof, productInput, position, measures)` |
| Python | `product_inputs.for_security(security, price, market_data)`, then `ValuationRequests.typed(asof, product_input, position, measures)` |
| JS/TS | `forSecurity(security, price, marketData)`, then `ValuationRequests.typed(asof, productInput, position, measures)` |
| Rust | `product_inputs::for_security(&security, &price, &market_data)`, then `valuation_requests::typed(asof, product_input, position, &measures)` |

The Python `ValuationService.run_valuation` helper already uses the builder. The price units are unchanged: bonds per 100 face, cash and equity per unit (`docs/adr/valuation_input_units.md`, row L6).

## Unmapped product types

The builder only maps product types that have a `ProductInput` arm in `hierarchy.json` `valuation_arms`. Every other type raises `UnmappedProductTypeError` naming the type. It never returns a request with `product_input` unset. Today these `ProductTypeProto` values have no arm: `PRODUCT_TYPE_UNKNOWN`, `EQUITY_INDEX`, `BOND_INDEX`, `COMMODITY_INDEX`, `VIX_SPOT`, `CPI_SERIES`, `SOFR_SERIES`, `T_BILL_13_WEEK_SERIES`, `FX_SPOT`, `CRYPTOCURRENCY`, `STABLECOIN`, `GOLD` and `SILVER`.

## Effect on callers

- **Java, JS/TS and Rust:** the accessors (`setSecurityInput`, `getPriceInput`, `security_input`, ...) are gone, so callers fail to compile until they move to the builder.
- **Python:** `ValuationRequestProto(security_input=...)` raises `ValueError`. Proto JSON that names either field fails to parse.
- **Old binary payloads** that still carry tags 20 or 22 parse, with the tags kept as unknown fields and ignored. A request with no `product_input` is handled by valuation-service (VS-145).

## Before tagging

Tag only after `VS-145` is in production and no consumer still sets either field (`LS-202`, `US-303`). Consumers declare a minimum ledger-models version, so they pick up this change at their next dependency update.
